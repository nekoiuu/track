# BigSeller – ดึงบันทึกการทำงานของคำสั่งซื้อ (Order Operate Log)

เอกสารนี้อธิบายว่าข้อมูล "บันทึกคำสั่งซื้อ" ในหน้ารายละเอียดคำสั่งซื้อของ BigSeller
(เช่น `สแกนและจัดส่งบน App และย้ายไปที่รอรับสินค้า  06 ต.ค. 2026 15:32:13 ajean@G963010029`)
มาจาก API ตัวไหน และต้องเรียกอย่างไร

> ข้อมูลได้มาจากการดู network request ของเว็บ BigSeller (www.bigseller.com) ตอนค้นหา
> เลขแทร็คกิ้ง `TH2650407991987` แล้วเปิดรายละเอียดคำสั่งซื้อ เมื่อ 06 ต.ค. 2026
> endpoint เหล่านี้เป็น API ภายในของหน้าเว็บ ไม่ใช่ Open API ทางการ อาจเปลี่ยนได้โดยไม่แจ้ง

---

## สรุปสั้น

| ข้อมูล | Endpoint |
|---|---|
| บันทึกการทำงาน (Order Log) | `GET /api/v1/order/operate/log.json?id={orderId}` |
| รายละเอียดคำสั่งซื้อ (สินค้า, ที่อยู่, โลจิสติกส์) | `GET /api/v1/order/detail.json?id={orderId}&historyOrder=0&viewBuyerMessage=false` |
| ค้นหาคำสั่งซื้อ (เช่น ด้วยเลขแทร็คกิ้ง) เพื่อเอา `orderId` | `POST /api/v1/order/new/pageList.json` |
| ป้าย/เครื่องหมายคำสั่งซื้อ | `GET /api/v1/order/getOrderLabel.json?orderId={orderId}&shopId={shopId}&orderNotApproved=false&historyOrder=false` |

Base URL: `https://www.bigseller.com`

> `orderId` คือ **ID ภายในของ BigSeller** (เช่น `16013081697`)
> ไม่ใช่เลขแทร็คกิ้ง (`TH2650407991987`), ไม่ใช่เลขคำสั่งซื้อ Shopee (`261005SCE5U9XS`)
> และไม่ใช่เลข BSG (`BSG9631X65270`)

## ขั้นตอน: จากเลขแทร็คกิ้ง → Log

### 1. ค้นหาคำสั่งซื้อเพื่อเอา `orderId`

```
POST https://www.bigseller.com/api/v1/order/new/pageList.json
```

หน้าเว็บเรียก endpoint นี้ตอนค้นหาด้วยเงื่อนไข "หมายเลขแทร็คกิ้ง" + "แม่นยำ"
ผลลัพธ์แต่ละรายการมีฟิลด์ `id` = `orderId` ที่ใช้ในขั้นต่อไป

> ยังไม่ได้บันทึก request body ที่แน่นอน ให้เปิด DevTools → Network → เลือก request
> `pageList.json` → แท็บ Payload แล้วคัดลอกรูปแบบมาใช้

### 2. ดึงบันทึกการทำงาน

```
GET https://www.bigseller.com/api/v1/order/operate/log.json?id=16013081697
```

#### ตัวอย่าง response (ตัดให้สั้นลง)

```json
{
  "code": 0,
  "msg": "Successfully",
  "data": [
    {
      "orderId": 16013081697,
      "orderStatus": "รอรับสินค้า",
      "minTime": "06 ต.ค. 2026 15:32:13",
      "beforeOperateLogDetails": [
        {
          "userName": "ajean@G963010029",
          "contentKey": "สแกนและจัดส่งบน App และย้ายไปที่รอรับสินค้า",
          "operateDate": "06 ต.ค. 2026 15:32:13",
          "ignoreOrderStatus": false
        }
      ],
      "afterOperateLogDetails": [
        {
          "userName": "ajean@G963010029",
          "contentKey": "พิมพ์รายการจัดส่ง",
          "operateDate": "06 ต.ค. 2026 16:07:24",
          "ignoreOrderStatus": false
        }
      ]
    }
  ]
}
```

#### โครงสร้างข้อมูล

- `data[]` แบ่งเป็นกลุ่มตาม **สถานะคำสั่งซื้อ** (เรียงจากใหม่ → เก่า)
  - `orderStatus` ชื่อสถานะ (ภาษาตามที่ตั้งค่าบัญชี เช่น `รอรับสินค้า`, `กำลังดำเนินการ`)
  - `minTime` เวลาที่เข้าสถานะนี้
  - `beforeOperateLogDetails[]` การกระทำที่ทำให้ย้าย **เข้า** สถานะนี้
  - `afterOperateLogDetails[]` การกระทำอื่นที่เกิดขึ้น **ระหว่าง** อยู่ในสถานะนี้ (อาจเป็น `null` หรือ `[]`)
- แต่ละ log มี
  - `userName` ผู้ทำ: บัญชีย่อยรูปแบบ `ชื่อ@รหัสบัญชี` หรือ `ซิงค์แพลตฟอร์ม` เมื่อระบบซิงค์จาก Shopee/Lazada/TikTok
  - `contentKey` ข้อความการกระทำ (เป็นข้อความที่แปลแล้ว ไม่ใช่ key/code)
  - `operateDate` เวลา (รูปแบบ `DD ต.ค. YYYY HH:mm:ss`, เวลาไทย, ปี ค.ศ.)

> `contentKey` และ `operateDate` เป็นข้อความตามภาษาที่ตั้งค่าในบัญชี
> ถ้าจะ parse ด้วยโค้ด ควรตั้งบัญชีเป็นภาษาอังกฤษ หรือแปลงชื่อเดือนภาษาไทยเอง

## การยืนยันตัวตน (Authentication)

- API ใช้ **session cookie** ของการล็อกอินเว็บ BigSeller (ไม่มี API key แยก)
- ถ้าเรียกจากสคริปต์ ต้องแนบ cookie จากเบราว์เซอร์ที่ล็อกอินอยู่ ซึ่งจะหมดอายุเมื่อออกจากระบบหรือ session หมดเวลา
- สิทธิ์ที่เห็นข้อมูลขึ้นกับบัญชี/บัญชีย่อยที่ล็อกอิน
- **อย่า commit cookie หรือ token ลง repository**

### ตัวอย่างเรียกด้วย curl

```bash
curl "https://www.bigseller.com/api/v1/order/operate/log.json?id=16013081697" \
  -H "Cookie: <คัดลอกจาก DevTools ของเบราว์เซอร์ที่ล็อกอินอยู่>"
```

## ข้อควรระวัง

- เป็น API ภายในของหน้าเว็บ: ไม่มีเอกสารทางการ, รูปแบบอาจเปลี่ยน, และการเรียกอัตโนมัติจำนวนมากอาจขัดกับข้อตกลงการใช้งานของ BigSeller
  ถ้าต้องการใช้งานระยะยาว แนะนำให้สอบถาม BigSeller เรื่อง Open API ทางการ
- คำสั่งซื้อที่เกิน 90 วันจะย้ายไป "ประวัติคำสั่งซื้อ" พารามิเตอร์ `historyOrder` ใน `detail.json` น่าจะใช้สลับไปดูคำสั่งซื้อในประวัติ (ยังไม่ได้ทดสอบ ให้ตรวจจาก network request ในหน้าประวัติคำสั่งซื้อ)
- ข้อมูลผู้ซื้อ (ชื่อ, เบอร์, ที่อยู่) ใน `detail.json` เป็นข้อมูลส่วนบุคคล ควรจัดเก็บอย่างระมัดระวัง
